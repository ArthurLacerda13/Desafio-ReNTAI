# 5. Desacoplamento do Motor de Inteligência Artificial via Strategy Pattern

## Status
Pendente

## Contexto
O núcleo inovador do edital do desafio técnico (Seção 2.4) foca na triagem automatizada e validação inteligente de anexos clínicos no exato momento do upload, mitigando o desperdício de tempo clínico do médico Especialista com arquivos corrompidos ou ilegíveis. O requisito **RNF004 (Desacoplamento do Motor de IA)** exige explicitamente que a arquitetura do backend isole essa integração através de interfaces abstratas intercambiáveis, permitindo alternar de forma transparente entre uma API real e um modelo simulado (*mock*) exclusivamente por configurações de ambiente.

Complementarmente, o requisito **RNF003 (Parametrização do Limiar)** proíbe terminantemente o uso de valores fixos no código (*hardcoding*) para o corte de aceitação do score da IA, exigindo leitura dinâmica via arquivo de variáveis de ambiente (`.env`).

Precisamos desenhar um padrão de arquitetura no backend Django que isole completamente as regras de negócio de teleconsultoria das especificidades técnicas das requisições de IA, garantindo que o sistema funcione perfeitamente em modo offline/desenvolvimento sem quebrar o fluxo de entrega do MVP.

## Decisão
Decidimos adotar o padrão de projeto comportamental **Strategy** combinado com o princípio da **Inversão de Dependência (DIP)** da metodologia SOLID para isolar o motor de Inteligência Artificial, estruturado através dos seguintes componentes:

1. **Contrato Abstrato (Interface):** Criação de uma classe base abstrata em Python chamada `BaseAIEngine` que define a assinatura do método obrigatório `validate_document(file_path: str) -> dict`. Essa assinatura padroniza o retorno esperado, que deve conter o score numérico, o provedor ativo, o limiar aplicado e o timestamp.
2. **Implementações Concretas (Strategies):**
   * `RealAIEngine`: Classe que encapsula o cliente HTTP, trata as conexões com as APIs reais de processamento de imagem/IA, realiza o parsing e devolve o payload estruturado.
   * `MockAIEngine`: Classe simuladora utilizada para testes locais e homologação da banca examinadora. Ela lê o threshold ativo no `.env`, gera um score simulado (controlável por parâmetros) e retorna o payload idêntico ao modelo real sem realizar chamadas de rede externas.
3. **Fábrica de Instanciação Dinâmica (Engine Factory):** Uma classe `AIEngineFactory` interceptará as inicializações do serviço. Ela lerá a variável de ambiente `AI_PROVIDER` (configurada no arquivo `.env` do Docker). Se o valor for `MOCK`, o backend injetará a classe simulada; se for `REAL`, injetará o motor integrado. O core do backend (as views/controllers de teleconsultoria) conhecerá apenas a abstração `BaseAIEngine`.

### Alternativas Descartadas
* **Condicionais Simples Injetadas nas Views (`if/else` estrutural):** Descartado de imediato. Inserir blocos como `if settings.AI_MODE == 'MOCK':` diretamente no fluxo de criação de teleconsultorias viola o princípio Open/Closed (SOLID), espalha código de teste no ambiente de produção e engessa a arquitetura, tornando a manutenção caótica caso novos provedores de IA sejam adicionados no futuro pelo ReNTAI.

## Consequências

### Pontos Positivos (Ganhos)
* **Aderência Total e Inquestionável ao Edital:** Atende 100% aos requisitos RNF003 and RNF004, demonstrando uma aplicação elegante e madura de padrões de projeto orientados a objetos (Design Patterns).
* **Isolamento de Ambiente e Testabilidade:** Permite que a suíte de testes automatizados do backend rode de forma extremamente rápida e determinística no pipeline de CI/CD ou no terminal da banca examinadora, sem depender de conexão com a internet, chaves de API pagas ou disponibilidade de serviços externos de IA.
* **Substituibilidade Transparente:** Se amanhã o consórcio LAVID decidir trocar o modelo de classificação de documentos (ex: migrar de uma API própria para uma solução em nuvem como AWS Textract ou Google Document AI), bastará criar uma nova classe concreta que herde de `BaseAIEngine`, sem alterar sequer uma linha de código das regras de negócio de abertura de chamados.

### Pontos Negativos (Custos / Trade-offs)
* **Esforço Inicial de Abstração:** Adiciona complexidade estrutural inicial no repositório de código do backend através da criação de arquivos específicos para contratos, fábricas e gerenciamento de injeção de dependências.
* **Padronização Rígida de Exceções:** Exige atenção redobrada no tratamento de erros. A classe `RealAIEngine` deve capturar falhas de rede ou timeouts HTTP de APIs de terceiros e envelopá-las em exceções customizadas do sistema (ex: `AIEngineConnectionError`) para que o core do sistema saiba tratá-las de forma idêntica e amigável na interface do usuário.
