# ADR-001 - Escolha da Stack

## Status
Aceito

## Contexto
O Módulo de Teleconsultoria (Plataforma V4H — Projeto ReNTAI) possui restrições arquiteturais e de negócio severas estabelecidas pelo consórcio gestor (LAVID/UFPB, RNP e FUNETEC-PB)
1. **Comunicação Ativa e Instantânea:** Atualização dinâmica de dashboards e envio de notificações em tempo real via WebSockets, eliminando recarregamentos de tela.
2. **Triagem Inteligente:** Consumo e integração com serviços de Inteligência Artificial para validação automatizada de anexos clínicos.
3. **Segurança e Isolamento:** Controle de acesso hierárquico (RBAC) baseado em sessões seguras via tokens JWT.
4. **Portabilidade e Governança:** Execução uniforme das camadas de software via contêineres Docker e disponibilização do código em repositório público para fins de auditoria acadêmica e transferência tecnológica.

## Decisão
Decidi adotar a seguinte composição de stack tecnológica para o desenvolvimento do ecossistema:

* **Frontend (Apresentação): Next.js (React / TypeScript)**
  Justificativa: Fornece uma arquitetura robusta para criação de Single Page Applications (SPAs) reativas, facilitando a manipulação de estados do ecossistema de WebSockets e permitindo construir interfaces de alta usabilidade e escaneabilidade visual para Solicitantes e Especialistas.
* **Backend (Regras de Negócio e Integração): Django (Python Framework)**
  Justificativa: Python é a linguagem soberana e padrão da indústria para manipulação de dados e ecossistemas de Inteligência Artificial. O ecossistema Django traz um sistema nativo e maduro de middlewares e ORM, acelerando a implementação de autenticação JWT, controle de rotas por perfis (RBAC) e o isolamento abstrato do motor de triagem por IA.
* **Banco de Dados (Persistência): PostgreSQL**
  Justificativa: Atende diretamente ao requisito de persistência relacional (RNF007), fornecendo total conformidade com transações ACID. Possui excelente suporte nativo para tipos de dados estruturados e semiestruturados (campos JSONB), facilitando o armazenamento dos logs brutos de auditoria exigidos para os retornos da IA.
* **Orquestração e Implantação: Docker e Docker Compose**
  Justificativa: Cumpre estritamente a restrição RNF006. Isola todas as dependências do ambiente (Frontend, Backend e Banco) em contêineres independentes, eliminando o problema de "funciona apenas na minha máquina" e mitigando atritos na avaliação técnica da banca examinadora.
* **Versionamento de Código: GitHub**
  Justificativa: Plataforma padrão para hospedagem e versionamento de código aberto. Permite manter o código-fonte perfeitamente organizado, público e documentado em conformidade com as políticas institucionais de uso gratuito e auditoria do Sistema Único de Saúde (SUS).

### Alternativas Descartadas
* *Backend em Node.js (Express) ou Java (Spring Boot):* Embora forneçam excelente desempenho para WebSockets, foram descartados devido ao fato de o Python (via Django) possuir maior sinergia nativa e bibliotecas mais consolidadas para lidar com tratamentos e integrações diretas voltadas à Inteligência Artificial, que constitui o núcleo inovador do edital.

## Consequências


### Pontos Positivos (Ganhos)
* **Sinergia com IA:** O backend em Python simplifica drasticamente qualquer lógica futura de manipulação de dados ou acoplamento direto com serviços de inteligência artificial.
* **Segurança Acelerada:** O ecossistema do Django acelera de forma nativa e segura a implementação de regras de restrição de acesso por perfil (RBAC).
* **Ambiente de Homologação Confiável:** Graças ao Docker Compose, a banca examinadora do LAVID conseguirá inicializar a aplicação completa localmente com um único comando no terminal.
* **Transparência e Conformidade:** O uso do GitHub cumpre a exigência de repositório público e auditoria exigida pela parceria UFPB/RNP.

### Pontos Negativos (Custos / Trade-offs)
* **Gerenciamento Assíncrono no Backend:** O Django é tradicionalmente síncrono. Para suportar conexões WebSocket persistentes com estabilidade e desempenho (conforme o RNF002), exigirá uma configuração e arquitetura adicionais no ecossistema de concorrência (como o uso do Django Channels ou integração assíncrona dedicada), elevando marginalmente a complexidade inicial de infraestrutura do backend.
